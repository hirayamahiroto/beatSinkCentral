# token-report

## 目的

「どの指示・どのフェーズ・どの領域に何トークン使ったか」を PR 単位で残し、ROI 判断の材料にする。
データ源は手元の `~/.claude/projects/` 配下のトランスクリプトなので、CI ではなくローカルから実行する。

## 手順

1. 対象を決める。現在のブランチなら引数なし、PR 番号があれば `--pr <n>`。
2. まず投稿せずに出力を確認する。

   ```bash
   npm run token-report -- --pr <n>
   ```

3. 内容に問題がなければ `--post` で PR コメントに投稿する。同じ PR に既存のレポートがあれば上書き更新される。

   ```bash
   npm run token-report -- --pr <n> --post
   ```

4. 指示文を表に含めたいときだけ `--include-prompts` を付ける。**このリポジトリは公開なので、PR コメントには既定どおり含めない。**

## 読み方

- 「入力総量」がコストの主因。cache read の割合が高く、値が大きいほど「長いコンテキストを何度も読み直した」ことを示す。
- 「フェーズ別」で調査の比率が実装を大きく上回るなら、着手前の設計・計画の停止地点を見直す。
- 「変更 1 行あたり」は PR 間の比較に使う。同種の変更で桁が違えば、セッションを切る・自律実行の範囲を区切る、といった運用の調整余地がある。
- 帰属は近似（ツール実行を含む API 呼出のトークンを、その呼出内のツールに等分）。厳密な原価計算ではなく傾向を見るためのもの。

## 注意

- `main` 上での作業はどの PR にも帰属しない。PR 単位で見たいなら着手時にブランチを切る。
- 概算額は Claude API 公開単価による API 相当額。単価表は `scripts/token-usage-report/lib.mjs` の `PRICE_PER_MTOK`。単価未登録のモデルは額に含まれず、その旨がレポートに出る。
