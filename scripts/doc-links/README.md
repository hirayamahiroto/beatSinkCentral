# doc-links — ドキュメントの参照切れを検出する

設計ドキュメントは相互に参照し合い、CLAUDE.md と Skill はそれを入口として指す。ファイルの移動・改名・見出しの変更で参照が切れると、エージェントも人も規範に辿り着けなくなる。これを PR ごとに機械で止める。

```bash
npm run docs:links        # 参照切れがあれば一覧を出して exit 1
npm run docs:links:test   # 検査器自身のテスト
```

CI は `.github/workflows/doc-links.yml` で全 PR に対して実行する。依存なし（Node のみ）。

## 何を検査するか

| 対象 | 範囲 | 確かめること |
| --- | --- | --- |
| Markdown リンク `[text](path#anchor)`・参照形式 `[ref]: path` | 追跡済みの `.md` と、gitignore 対象外の未追跡 `.md` | ファイル（ディレクトリ可）が在ること。`.md` へのアンカーは見出しが在ること |
| バッククォートのパス `` `docs/…` `` `` `.claude/…` `` `` `scripts/…` `` | 下記の除外を除く `.md` | パスが在ること（`#` `:` 以降は無視） |
| コード中の `docs/…` `.claude/…` | `.ts` `.tsx` `.mjs` `.mts` `.yml` `.yaml` | パスが在ること |

見出しアンカーは GitHub と同じ規則で作る（小文字化し、文字・数字・`_`・空白・`-` 以外を落とし、空白を `-` にする。重複は `-1` `-2`）。`<a id="…">` も受け付ける。

## 検査しないもの

- 外部 URL（`http:` `mailto:` 等）。到達確認はネットワークに依存して不安定になるため
- コードフェンス内
- 書式の例示・glob・変数（`...` `…` `*` `{}` `<>` `$` を含むもの）と、gitignore 済みのパス
- **バッククォートのパスに限り** `docs/adr/` `docs/plans/` `docs/discussions/`。規範でない場所（CLAUDE.md「ドキュメントの構成」）で、廃止したファイルや未作成のファイルに言及するのが正当なため。Markdown リンクはここでも検査する
- `apps/` `packages/` のパス。検討資料の `file:line` 付きスナップショットが多く、コードの変更で当然ずれるため

## 直し方

出力は `ファイル:行  参照先  （理由）`。

- ファイルを移動・改名したら、参照元も同じ PR で直す（`git grep` で旧パスを探す）
- 見出しを変えたら、アンカーで参照している箇所を直す
- 除外や設定を変えるときは `index.mjs` 冒頭の「設定」ブロックを変え、`index.test.mjs` に検出・非検出のケースを足す
