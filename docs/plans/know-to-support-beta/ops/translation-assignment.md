# 翻訳あり／なしの割り付け表

> H4（翻訳）を検証するために、参加者を翻訳あり群／なし群に**開始前に固定**する。根拠は [`prd.md`](../../../discussions/prd/know-to-support-verification/prd.md) H4・§7-3・§7-4 週 0・§9-1（あり群は 3〜4 人分のみ）。
> **時限ドキュメント**（[`plan.md`](../plan.md) の T11）。

---

## 1. 使いどころ

- 週 0、参加者が確定し聞き取り①が終わった時点で埋め、**Story 執筆（週 1）が始まる前に固定**する
- 固定後は動かさない。動かすと H4 の比較（あり群 vs なし群の非ビートボクサー来場率）が壊れる
- あり群の翻訳段落は運営が書き、[`translation-confirmation-flow.md`](./translation-confirmation-flow.md) で本人確認してから公開する

## 3. 割り付け手順

PRD は「二分する」「あり群は 3〜4 人」までしか決めていない。以下の手順は**案**。

1. 参加者全員の聞き取り①が終わっていることを確認する（本人の言葉を知らずに翻訳は書けない）
2. 参加者を「ベータ期間中のライブ予定の本数」と「地域コミュニティ」で並べる
3. ライブ予定が **1 本以上ある人**の中から、あり群を 3〜4 人選ぶ。ライブ予定が無い人をあり群に入れると来場率が測れない
4. あり群が特定のコミュニティに偏らないようにする（あり群の全員が同じ地域なら、地域差と翻訳の差が分けられない）
5. 上記で候補が絞れなければ、残りは抽選で決める。「書きやすそうな人」で選ばない（翻訳の書きやすさで結果が歪む）
6. 表を埋め、固定日を記入する。以後の変更は行わない
7. 本人への伝え方: あり群の人には翻訳の下書きを送る段階（週 2〜3）で「運営が『何が凄いか』を書いた段落を載せたい」と伝える。なし群の人には翻訳の存在を積極的には伝えない（[`outreach-message.md`](./outreach-message.md) §3）

## 4. 固定後に起きうること

| 起きること                           | 扱い                                                                          |
| ------------------------------------ | ----------------------------------------------------------------------------- |
| あり群の人がベータを離脱した         | 補充しない。あり群が 2 人になったら H4 は「傾向のみ」として §8 の判断に添える |
| なし群の人が翻訳を書いてほしいと言う | ベータ中は書かない。終了後（§9-2 の長期方針が決まった後）に対応すると伝える   |
| あり群の人が翻訳の公開を断った       | 本人の意向を優先し公開しない。表に「本人確認: 不可」と残し、H4 の母数から外す |
