# ライブ翌日の記録メールの運用手順

> 受信登録者（F7）に、ライブ翌日「昨日の記録（写真 1 枚＋一言）」を**手動で**送る。[`concept-and-loops.md`](../../../discussions/prd/know-to-support-verification/concept-and-loops.md) §5 の採用候補で、H5（戻り道）を「次の告知」より早く検証する手作業実験。機能化しない（同 §6 項目 4）。
> **時限ドキュメント**（[`plan.md`](../plan.md) の T11）。宛先のメールアドレスはこのリポジトリに書かない（checklist §4-3）。

---

## 1. 何を送るか

| 要素         | 内容                                                                 | 出典                         |
| ------------ | -------------------------------------------------------------------- | ---------------------------- |
| 写真 1 枚    | 昨日のライブの写真。アーティスト本人から受け取る                     | concept-and-loops §5         |
| 一言         | アーティスト本人の一言（そのライブで何を表現したか）。運営は書かない | concept-and-loops §3-2「色」 |
| ページの URL | 本人の公開ページ（`?from=share` 付き）                               | PRD §6-1 `from`              |
| 解除 URL     | 受信解除の URL（T09 #280 で必須）                                    | T09 最終挙動                 |

> **案**: 一言は本人の言葉に限る（運営の言葉が混ざると §2-4 の分離が崩れる）。写真の掲載可否は本人が判断し、来場者の顔が写るものは避ける。

## 2. 文面

```
件名: 昨日の〇〇（アーティスト名）のライブの記録

（写真 1 枚）

〇〇さんから一言:
「（本人の一言）」

〇〇さんのページ: https://…/players/〇〇?from=share

---
このメールは、〇〇さんのページで「次の告知を受け取る」に登録した方にお送りしています。
受信をやめる: （解除 URL）
```

> **案**（PRD §6-2 と統合する場合）: 来場確認の一問「昨日のライブに行きましたか」を文末に 1 行足す。返信で受け取る。足すかどうかは T09 の同意文言（「ライブ翌日の一問への利用可否」）が決まってから確定する。

## 3. 手順（ライブ翌日）

| 順  | やること                                                                         | 誰が       |
| --- | -------------------------------------------------------------------------------- | ---------- |
| 1   | ライブ当日〜翌朝に、本人へ「写真 1 枚と一言」を依頼する（依頼文は §4）           | 運営       |
| 2   | 本人から写真と一言を受け取る。届かなければ送らない（運営が代わりに書かない）     | 運営・本人 |
| 3   | T13 の SQL で、そのアーティストの受信登録者の宛先を取り出す（解除済みを除く）    | 運営       |
| 4   | §2 の文面で送る。宛先は 1 通ずつ、または BCC（他の登録者にアドレスが見えない形） | 運営       |
| 5   | 送信の記録（§5）を残す。宛先リストはメーラーの外に保存しない                     | 運営       |
| 6   | 返信・解除があれば記録し、返信の内容は聞き取り③ Q3-2 の材料にする                | 運営       |

> **案**: 送信は翌日中。2 日以上空いたら「記録」の鮮度が落ちるので送らず、次のライブで送る。

## 4. 本人への依頼文

```
昨日はお疲れさまでした。
ページで「次の告知を受け取る」に登録してくれた人に、昨日の記録を送りたいと思っています。
写真 1 枚と、一言（昨日のライブで何を表現したか、どんな回だったか）をもらえますか。
一言はそのまま載せるので、〇〇さんの言葉でお願いします。
```

## 5. 送信の記録（1 ライブ 1 行）

| 仮 ID | ライブ日 | 送信日 | 宛先数 | 返信数 | 解除数 | 次のオファーでの再訪（T13 で照合） | 備考 |
| ----- | -------- | ------ | ------ | ------ | ------ | ---------------------------------- | ---- |
|       |          |        |        |        |        |                                    |      |

宛先数・返信数・解除数は数だけ残す。誰が返信したかは残さない。

## 6. T09（受信登録）が未実装の間の宛先の扱い

T09（#280）がマージされるまで、ページに登録フォームが無く、`notify_subscriptions` に宛先が入らない。この間の扱いは PRD に無いので、以下を**案**として置き、着手前にユーザーが選ぶ。

| 案  | 内容                                                                                                                                                     | 得られるもの             | 注意                                                                                                              |
| --- | -------------------------------------------------------------------------------------------------------------------------------------------------------- | ------------------------ | ----------------------------------------------------------------------------------------------------------------- |
| A   | T09 が入るまで記録メールは送らない。週 3 以降のライブから始める                                                                                          | 手順が一本で済む         | 週 3 より前のライブは H5 の材料にならない                                                                         |
| B   | 運営が管理する外部フォーム（登録目的・解除方法・ライブ翌日の一問への利用可否を明記）を、T09 と同じ文言で用意し、ページの戻り道区画の代わりに告知に添える | T09 前のライブでも送れる | フォームの宛先は T09 マージ後に本人の同意の範囲で移す。移せなければ破棄。PRD F7「フォーム＋手動送信で可」の範囲内 |

- どちらの案でも、**同意していない宛先には送らない**（アーティストが持っている顧客リストや DM の相手に送らない）
- 案 B を選ぶ場合、フォームの同意文言は T09 の「着手前に決めること」と同じものを使い、二重に決めない
