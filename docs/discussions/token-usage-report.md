# 検討メモ — Claude Code トークン使用量の PR 単位レポート

> 位置づけ: `discussions/`（検討中）。運用が定着したら `architecture/` 配下の開発プロセス系ドキュメントへ昇格する。

## 背景

AI への指示に対して消費されるトークンが増え、ROI が合わなくなってきた。2026-08-08〜09-05 の 76 セッションを集計したところ、次の構造が見えた。

| 観測                                  | 値                                                      |
| ------------------------------------- | ------------------------------------------------------- |
| 指示 1 回あたりの入力総量             | 約 174 万トークン（API 呼出 7.9 回、ツール実行 8.1 回） |
| 入力総量に占める cache read           | 98%                                                     |
| 費用（API 相当額）に占める cache read | 6 割超。出力は 1 割強                                   |
| API 呼出のコンテキスト中央値          | 178k（200k 超の呼出がトークン総量の 68%）               |
| `main` 上で消費されたトークン         | 全体の約 27%（どの PR にも帰属しない）                  |

費用を決めているのは生成量ではなく「毎回読み直すコンテキストの大きさ × ツール呼び出し回数」だった。

## 決めたこと

- **PR 単位でレポートを残す。** ブランチ名で紐づける（トランスクリプトの各レコードに `gitBranch` がある）。
- **ローカルから投稿する。** データは `~/.claude/projects/` にしかなく CI からは見えないため、CI で集計する設計は取らない。`scripts/token-usage-report/` を `npm run token-report -- --pr <n> --post` で実行し、`gh` で PR コメントを upsert する。
- **指示文は既定で載せない。** リポジトリが公開のため。`--include-prompts` は明示的な opt-in。
- **帰属は近似で割り切る。** ツール実行を含む API 呼出のトークンを、その呼出内のツールに等分してフェーズ（調査 / 実装 / 検証 / 実行 / 委譲）と領域（`apps/*`, `packages/*`, `docs` など）に帰属させる。厳密な原価ではなく傾向を見るための指標。

## 見送ったこと

- **集計結果 JSON をブランチにコミットして CI がコメント化する案。** 履歴をリポジトリに残す動機が今はなく、差分ノイズが増える。
- **OpenTelemetry でテレメトリを外部ストアへ送り CI が取得する案。** インフラが増える。ローカル投稿で足りる。
- **フックで `gh pr create` 直後に自動投稿する案。** まず手動運用（`token-report` Skill）で定着させ、その後に自動化を判断する。

## 打ち手（レポートを見て調整するもの）

1. セッションをタスク単位で切り、長い会話を引きずらない。
2. 「進めて」の一言で長い自律実行に入る前の停止地点を Skill 側に置く。
3. 探索・調査はサブエージェントや Sonnet に寄せ、メインのコンテキストを汚さない。
4. 作業種別でモデルを分ける（ドキュメント編集・単純修正は Sonnet 5）。
