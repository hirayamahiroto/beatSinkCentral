# T10: 「次の告知を受け取る」（メール受信登録）

| 項目 | 内容              |
| ---- | ----------------- |
| 対応 | F7, H5 / PRD §5-1 |
| 種別 | 作る              |
| 依存 | T02, T08          |
| 規模 | M                 |

## 背景

H5（戻り道）の仕込み。最小実装＝「フォーム＋手動送信で可」（PRD F7）。送信の自動化は作らない。

## スコープ

### やること

- **DB**: `notify_subscriptions` テーブル（`artist_profile_id` fk / メールアドレス / 登録日時 / 解除トークン）。**メールアドレスは PII** — `analytics_events` とは別テーブルに分離し、ログ・エラーメッセージに生値を出さない（checklist §4-3）
- **UI**: 詳細ページ区画 6 のメール入力フォーム（未ログインで登録可）
- **イベント**: 登録成功時に `notify_subscribe` を発火（イベント側にメールアドレスは載せない）
- **解除**: 配信メール記載用の解除 URL（ワンクリック解除）。最低限これだけは最初から持つ
- **送信は手動**: 運営が登録者一覧を SQL で取り出し、手でメールを送る。取り出し手順を T14 の SQL 集に含める

### やらないこと

- 配信基盤・テンプレート・自動送信（H5 が成立してから）
- ダブルオプトイン（ベータ規模では省略。ただし解除は必須）

## 受け入れ条件

- [ ] アーティスト単位で登録でき、同一メールの重複登録が増殖しない
- [ ] `notify_subscribe` イベントと購読テーブルの件数が突き合う
- [ ] 解除 URL で解除できる
- [ ] メールアドレスがログ・イベント・エラーメッセージのどこにも生で出ない

## 着手前に決めること

- 同意文言（受信目的の明示）と、ライブ翌日の一問アンケート（§6-2）への利用可否を登録時に含めるか
