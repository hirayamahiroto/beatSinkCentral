# T11: 共演者からの招待リンク

| 項目 | 内容              |
| ---- | ----------------- |
| 対応 | F9, H6 / PRD §5-1 |
| 種別 | 作る              |
| 依存 | T02, T05          |
| 規模 | M                 |

## 背景

H6（紹介）の仕込み。オファーの共演者欄から、未登録アーティストへ招待コード付き登録 URL を渡す。「繋がりから発見が生える」（PRD §2-3）の最初のデータでもある。

## スコープ

### やること

- **DB**: `invites` テーブル（招待コード / `inviter_artist_id` fk / 対象の共演者表示名 / 使用状況）
- **発行**: オファーの共演者（未登録）に対して招待 URL を発行できる（本人の編集画面から。運営代行でも可）
- **導線**: 詳細ページ区画 7（繋がり）で、未登録の共演者名に招待の受け口を出す
- **登録フロー接続**: 招待 URL → 既存のサインアップ / オンボーディングに `invite` 文脈を引き回し、登録完了時に招待を消費。共演者欄の表示を登録済みプロフィールへのリンクに差し替える
- **イベント**: `invite_open`（招待 URL を開いた）/ `invite_signup`（招待経由で登録完了）。props に `inviter_artist_id`
- 招待コードは推測不能な値。有効期限と再発行を持つ

### やらないこと

- 招待の一覧管理画面・招待メールの自動送信（URL を手で渡す）
- 招待経由で入った新人の Story 執筆サポート（T12 の運用側）

## 受け入れ条件

- [ ] 招待 URL から登録完了まで通り、`invite_open` → `invite_signup` が同じ招待コードで連結できる
- [ ] 登録完了後、オファーの共演者表示がプロフィールリンクに変わる
- [ ] 使用済み・期限切れコードは明示的なエラーで落ちる（静かに素通りさせない）
- [ ] usecase / repository にテストがある

## 着手前に決めること

- 招待経由の登録者を自動でベータ対象に含めるか（PRD §2-5 は「後から入る」）
