# T08: 詳細ページの §5-2 再構成（7 区画・オファー状態・空区画非表示）

| 項目 | 内容               |
| ---- | ------------------ |
| 対応 | PRD §5-2           |
| 種別 | 作る               |
| 依存 | T04, T05, T06, T07 |
| 規模 | L                  |

## 背景

大衆向けの動線本体。段階的開示を PRD §5-2 の順（引っかかり → 人 → 翻訳 → 聴きどころ → いま／一つの行動 → 戻り道 → 繋がり）に組み直す。ベータの検証は全てこのページの上で起きる。

## スコープ

### やること

- **区画の再構成**（§5-2 の 7 区画）。区画 6（戻り道）は T10、区画 7（繋がり＝招待）は T11 が実体を作る。本チケットは器（順序・レイアウト・出し分け）を持つ
- **オファーによる状態切り替え**: オファーあり期間は固定バーで常時表示＋hero にボタン。無い期間は Story 主役の平常レイアウトで、主 CTA は軽い応援（T00 の決定に従う）
- **空区画は描画しない**: 任意項目が空のとき区画ごと消す。「実績ゼロでも成立する」を空欄を出さないことで守る
- **未ログイン閲覧**: 詳細ページと BFF read 経路が未ログインで動くことの確認（公開 API の範囲は公開プロフィールのみ）
- **一覧には載せない**: ベータは URL 直アクセスのみ。一覧ページからのリンク・sitemap 掲載をしない（§5-3）。SEO はページ単体で成立させる（OGP は既存の名前・画像・タグライン）
- 主要操作ボタンは 1 区画 1 つ（§5-2 順 5「ボタン 1 つ」）

### やらないこと

- 前室（ストーリーズ形式）— T00 で「置く」と決まった場合のみ別チケットに切る
- 見た目の作り込み（§5-3。写真と文章が揃ってから）
- 一覧の DB 連携

## 受け入れ条件

- [ ] 7 区画が §5-2 の順で表示され、空の区画が存在しない
- [ ] オファーの有無でページの状態（固定バー・主 CTA）が切り替わる。判定は BFF から解決済みで渡り、UI に日付ロジックが無い
- [ ] 未ログイン・シークレットウィンドウで全区画が閲覧できる
- [ ] 非公開プロフィール・存在しない handle で情報（名前等）が漏れない
- [ ] T03 の各イベント発火点（DOM 上のフック）が揃っている
