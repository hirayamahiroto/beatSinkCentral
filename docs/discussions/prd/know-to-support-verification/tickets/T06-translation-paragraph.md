# T06: 翻訳段落（運営記入）

| 項目 | 内容                    |
| ---- | ----------------------- |
| 対応 | F3, H4 / PRD §5-1, §2-4 |
| 種別 | 作る                    |
| 依存 | T00                     |
| 規模 | S                       |

## 背景

H4（翻訳）の検証対象。運営が書く「この人の何が凄いか」一段落。**本人の言葉（Story）と運営の言葉（翻訳）を画面上で混ぜない**（PRD §2-4）。翻訳あり／なしの二分（H4）ができる必要がある。

## スコープ

### やること

- **DB**: `artist_profiles` に翻訳段落カラム（または 1:1 テーブル）。書き手が本人でないことがデータ構造上わかる形にする
- **入力**: 管理画面は**作らない**（PRD 明記）。運営が SQL / seed スクリプトで書き込む。書き込み手順を本チケットに追記して残す
- **表示**: 独立した区画（§5-2 順 3）。「運営による紹介」等、本人の言葉でないことが分かるラベルを付ける（ラベル文言は UI コピーとして UI 層に置いてよい）
- 翻訳なし群・未記入のときは区画ごと非表示

### やらないこと

- 運営用の編集 UI・承認フロー（ベータでは 3〜4 人分のみ。§9-1）
- 本人による編集（本人の言葉と混ざるため不可）

## 受け入れ条件

- [ ] 翻訳が無いプロフィールで区画が描画されない（空欄・枠だけの表示が無い）
- [ ] 表示上、本人の言葉と運営の言葉が視覚的に分離されている
- [ ] 運営の書き込み手順（SQL）が再現可能な形で残っている

## 運用上の注意（PRD §7-6）

- 公開前に**本人に事前確認**する（本人の言葉と食い違うと信頼を失う）。確認フローは T12 の運用キットに含める
